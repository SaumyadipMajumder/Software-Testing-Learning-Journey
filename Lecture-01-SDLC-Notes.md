Q) What is the difference between Verification and Validation?
Ans: The difference between verification and validation is that verification does the review of the process before executing or starting the development of the software itself, where we review walkthrough and inspect every process of the documentation from customer requirement specifications, system requirement specifications, HLD, and LLD. Whereas validation starts after the development of the software has done, and we start with the testing the built software itself with unit testing, integration testing, system testing, and user agreement testing. In simple terms, we, in verification, we verify the document before creating the development of the software itself, while in validation, we validate the software that has been developed itself, with the process of different testing.

Q) What is the difference between Static Testing and Dynamic Testing?
Ans: Static testing is basically the testing of the documents itself, where we like review the documents of different processes such as CRS, SRS, HLD, LLD documents, walk through with them, inspect them. That is a static process. Whereas in dynamic process, we test the software itself, where we have unit testing, integration testing, system testing, and UAT. In the static testing, because the whole process is static, it is the documents are itself static. But in the dynamic testing, we are running the software to check whether it behaves correctly. 

Q) Why is White Box Testing called "White Box" and Black Box Testing called "Black Box"? Who usually performs each one?
Ans: White box testing, white box testing called white box because it is something that is, can be only test when you know what is inside the box and you have the idea what is inside the box. In the case of software development, it is the code, the architecture, the design of the software in the internal itself. Whereas the black box testing called black box because in this you test the box itself, not what is inside the box. You do not have to know what is inside the box. You just have to ensure what is the, how the box is working and if it is working according to the requirement itself or not. Because you don't know what is inside the box, that's why it is called black box testing. White box testing is usually done by developers who write the code of the software itself. Black box testing is done by the testers who test the software after it has been developed.

Q) Suppose a client comes to your company and says: "I don't know exactly what software I want. I only have a rough idea."
Which SDLC model would you recommend?

Waterfall, Prototype, Spiral, V-Model

Explain why.

Ans: Prototype Model. Because the prototype helps the client discover their requirements before the full system is built. Whereas V-Model assumes the requirements are already well-defined and stable. If the requirements keep changing, the V-Model becomes expensive and difficult to manage.
